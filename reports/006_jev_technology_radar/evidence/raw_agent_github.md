## 3. Faits transverses établis (calibration, robustesse) — avec niveau de preuve

1. **Formule de la confiance (Choice)** `C = (N*p_max − 1)/(N − 1)`, donc *pas un signal indépendant* de p_max. Attribuée à Stanislav Yurin (bernoulli.app) puis primeline.cc et stillmarcus24/jev-verify. **PROVEN par moi** sur `jev-calibration-audit/results/raw/abstention.jsonl` (600 lignes/bras) : résidu moyen 0,0043 (max 0,015) avec N=3 pour le bras à 3 options ; 0,0038 (max 0,01) avec N=2 pour le bras à 2 options ; un mauvais N donne 0,033-0,057 moyen (max 0,26). Conséquence : un seuil sur `confidence` équivaut à un seuil sur p_max.
2. **Sorties quantifiées à 0,01**, pouvant valoir exactement 0 ou 1 (OBSERVED dans le JSONL ci-dessus ; SamuelSacco/jev-exploration). Jev-certify : confiance exactement 1,0 sur 56,4 % des réponses dont 9 fausses -> plancher de risque atteignable 1,95 % (DOCUMENTED_CLAIM, code cloné).
3. **Répétabilité** : quasi déterministe mais pas exact. jev-skillbench (OBSERVED, jsonl bruts) : 2 passes sur 963 skills, 64 % de scores identiques, écart absolu moyen 0,005, max 0,08, 5-6 skills franchissant 0,5. calibration-audit : 50 requêtes identiques -> 15 réponses distinctes. Cache client : pas de cache serveur observé.
4. **Absence d'option "aucune"** : accuracy KoBBQ 0,950 -> 0,000 quand l'option "unknown" est retirée (PROVEN sur brut : accuracy 0,958 avec option, 0,497 sans sur mon recalcul de abstention.jsonl : le brut cloné donne 0,497 et non 0,000, donc le "0,000" du README vise le sous-ensemble des items non résolvables ; ne pas citer 0,000 sans ce périmètre). priorbench : 0/30 hors-périmètre signalés sans option "none" ; recette au hasard classée 0,94-0,97.
5. **Injection** : le texte "évidence" (approbation revendiquée) marche, l'ordre brutal échoue. willkelly : "IGNORE…" déplace 1/200, "un lead a déjà décidé" 147/200 ; zkousama/jagged : précision 0,965 -> 0,265 avec une ligne injectée (ECE +0,451) ; cwhy/decision-injection-bench : 1/1056 flips (Jev) contre 3-62 % pour d'autres modèles. Résultats **contradictoires entre études** selon le type d'injection : INFERENCE -> ne pas tabler sur "immunité".
6. **Calibration dépend du domaine** : bonne sur routage support (ECE 0,075), effondrée hors distribution (3-SAT ; règle inconnue ECE 4,4x le plancher de bruit), sous-confiante sur injection (jev-sec-bench), sur-confiante sur d'autres (Banking77 0,094 ; Anthus : Noul 79,0 % annoncé vs 72,3 % réel, Choice 91,4 % vs 76,1 %). Recalibration isotonique (Anthus ECE 0,117 -> 0,008 ; skillbench 0,123 -> 0,010) ne se transfère pas entre jeux de données (d3code-calibration).
7. **Ordre / nombre d'options** : effet nul sur la plupart des tâches (0 flip sur 400) mais jusqu'à 0,37 sur questions de valeur ; dé équitable : 82,9 % de masse sur un choix à 19 % de justesse (Choice) alors que des Noul indépendants donnent ~1/6 ; l'effet croît avec le nombre d'options (DOCUMENTED_CLAIM ; code cloné pour jev-does-not-play-dice, non ré-exécuté).
8. **Découpage des questions** : 62,6 % en une question contre 95,0 % en cinq questions atomiques (phishing, DOCUMENTED_CLAIM) ; mais ElshinQ/jevaluate : le découpage a détruit la calibration. Batch de questions sur un même state : pas d'interférence (calibration-audit, willkelly) ; **plusieurs lignes/sujets par state** : dégradation si référencés par position (0,420 vs 1,000 par nom, willkelly).
9. **Pas de comptage / état séquentiel / calcul** : 13,2 % sur mutation d'état séquentielle, 33,3 % comptage exact (etsabary, DOCUMENTED_CLAIM). Le PLAN d'usage dominant : "Jev juge la sémantique, le code fait l'arithmétique" (buberlo, jev-crypto-scout).

## 5. Patterns d'usage récurrents (INFERENCE à partir du code lu)
1. **Jev juge, le code exécute** (buberlo, crypto-scout, jev-tm-reference, QuantDinger) ; vetos de risque hors modèle.
2. **Questions atomiques + composition en code** ; plusieurs questions dans une requête (gratuit d'après willkelly, priorbench) ; nommer le sujet dans la question quand plusieurs lignes partagent un state.
3. **Seuil et marge dans le code**, calibrés sur ses propres données (isotonique/Platt) ; gate haut (0,7-0,99 selon domaine) puis escalade vers humain ou LLM ; porte "stricte" = faux OU confiance < seuil.
4. **Option explicite `none`/`not_in_this_list`/`insufficient`** systématique (kyotofin, QuantDinger, calibration-audit).
5. **Contexte de déploiement dans le state** (+20 pts de rappel sur injection, jev-sec-bench) ; critères précis : levier principal (jusqu'à +26 pts) mais un critère faux est catastrophique.
6. **Hiérarchie de requêtes** pour grands nombres d'options (kyotofin 230 + sous-question).
7. **Repli et dégradation** : LLM de repli, pause 60 s à 10 min sur 429, fail-open (QuantDinger) ou fail-closed (approval-judge-bridge) : choix critique à expliciter.
8. **Journaliser (state, décision, résultat)** pour recalibrer (buberlo).

## 6. Failure modes consolidés (avec source)
- Toujours une réponse même hors périmètre (priorbench, calibration-audit) -> exiger option `none`.
- Confiance = f(p_max), quantifiée 0,01, 1,0 exact sur ~56 % (certify) ; choix parfois 0,01 sous le max (issue Python #15).
- Calibration non transférable entre domaines ; effondrée hors distribution (willkelly, scienthoon).
- Injection "d'évidence" efficace (jusqu'à 26,5 % de précision, jagged) ; la confiance baisse mais pas assez pour tout attraper.
- Limites : 32k tokens état + question, 64k total ; troncature -> rappel dégradé (skillbench) ; `max_tokens_exceeded`.
- Pare-feu Cloudflare 403 HTML sur contenu ressemblant à des commandes (issue JS #15, skillbench) ; console 500 pendant 2 jours (skills #10) ; 429 via passerelles (Vercel).
- Ruptures d'API des SDK : pydantic vs msgspec en 0.7.0, renommages de l'adapter ; clés API dans les messages d'erreur (Py #9, JS #14) ; validation client incomplète (noul vide, state null, score null).
- Adapter : all-zero -> option 1 (#45), troncature acceptée (#38, corrigé), refus ignorés (#46), pas de timeout (#48).
- Pas de valeur prédictive de marché démontrée : 6 études finance indépendantes convergent (jev-alpha-bench, jev_bitcoin_backtest, calibration-is-not-alpha, jev-edgar, Siim, tm-reference vs LR) ; seul JevGym (licence non commerciale, non vérifié) annonce un gain.
- Latence : médiane 280-430 ms selon région/passerelle ; jamais < 100 ms mesuré (Siim : 0/35 685).
- Étendue du corpus tiers : intérêts commerciaux/promo possibles (passerelle "officielle" dans SmartMoney-Cub, pubs) ; jev-verify signale des sorties fabriquées.
