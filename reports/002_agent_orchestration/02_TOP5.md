## 1. Absurd — `earendil-works/absurd` (Apache-2.0)
**What:** durable execution implemented entirely inside Postgres. One SQL file `sql/absurd.sql` (3150 lines, ~40 plpgsql functions) + SDKs (Python SDK 2317 lines, 1 dep: psycopg; TypeScript SDK). Optional dashboard (Habitat) and CLI (absurdctl). PROVEN.

| Aspect | Finding |
|---|---|
| Services | Postgres + worker processes you write/supervise. No broker/coordinator. PROVEN |
| Durable state | 5 tables per queue: `t_` tasks, `r_` runs (one row per attempt), `c_` checkpoints, `e_` events, `w_` waits. SQL-queryable. PROVEN |
| Worker lifecycle | `claim_task` = `FOR UPDATE SKIP LOCKED` + lease (`claim_timeout`; SQL default 30 s, experiment used 10 s). Checkpoint writes and `heartbeat` extend lease; `await_task_result` auto-heartbeats. PROVEN |
| Dead-worker recovery | **No reaper.** Expired leases are swept *inside `claim_task`* by any polling worker, at most `qty` runs per call (absurd.sql:965). Needs a live worker with a free slot. PROVEN |
| Fencing | A stale worker's complete/checkpoint on a reclaimed run raises AB002 (SDK swallows). Fences run state, **not** user side effects. PROVEN |
| Retry | none / fixed / exponential, 1-day cap. **Default = no strategy → immediate retry**; Python SDK `max_attempts` default 5. PROVEN |
| Semantics | at-least-once code; exactly-once only for checkpointed step *results*. PROVEN |
| Dependency graph | **None.** Tools: child task in a *different* queue + `ctx.await_task_result` (holds a worker slot; same-queue await rejected), events, sleep. Fan-out/fan-in is open issue #110. PROVEN/OBSERVED |
| Observability | SQL, Habitat UI, absurdctl (optional; not exercised). |
| Tests | ~161 SQL tests, ~93 Py SDK tests, ~100 TS tests; all need Docker + postgres:16. **No test kills a process or PG**; recovery is tested by `fake_now` time travel. PROVEN |
| PG 18.6 | Py SDK tests 93/93 pass after patching the fixture (Docker unavailable). SQL suite 107 pass / 4 fail: two uuidv7 tests + a partition-detach test (native PG18 `uuidv7()` ignores `fake_now` — INFERENCE: harness issue) and one lease-expiry index-plan assertion (INFERENCE: planner choice on tiny table). pg_cron e2e and absurdctl build tests not run. OBSERVED |
| Maintenance | 309 commits; last 2026-08-04 (release 0.5.0); **90 d: 6 commits, 1 author** (Ronacher 282/309 all time). pyproject marks Alpha. 22 open issues, none in visible titles about stuck/duplicate execution (closed count UNKNOWN). Lease-path fixes cluster March 2026 (89833e6, 39587e9, 300a5c2, b87b423) → young code. OBSERVED |
| Setup | PG + venv + install + schema: 19 s; first working pipeline ≈10 min. OBSERVED |
| Fit (INFERENCE) | Strong: one PG, stateless workers, per-step checkpoints, resume-by-construction, events/sleep for human-in-loop. Weak: no DAG, `claim_timeout` must exceed longest un-heartbeated step, recovery depends on live polling workers, no SDK reconnect, cleanup must be scheduled, alpha + single maintainer. |

## 2. DBOS Transact (Python) — `dbos-inc/dbos-transact-py` (MIT)
**What:** library, not a server. Only required service: Postgres (SQLite default for dev; CockroachDB supported). 6 direct deps, ~32.7k LOC (`_sys_db.py` 7.4k lines). PROVEN.

| Aspect | Finding |
|---|---|
| Durable state | `workflow_status` (~40 cols), `workflow_input/output`, `operation_outputs`, `notifications`, `workflow_events`, `streams`, `workflow_schedules`, `application_versions`, `queues`; 36 migrations. Step outputs **pickled** by default → opaque base64 in psql. PROVEN/OBSERVED |
| Ownership / lease | **No lease, no heartbeat, no dead-worker detection.** Ownership = `executor_id` string on PENDING rows. PROVEN |
| Recovery | Automatic **only at process launch** for rows where `executor_id` == own and `application_version` == own (`_dbos.py:697-711`, `_recovery.py:36-70`, `_sys_db.py:2675`). Recovering *another* executor's work is reachable only from the Conductor websocket handler (`conductor.py:178`) or private `_recover_pending_workflows`. Skipped entirely when `conductor_key` set. PROVEN |
| Defaults that bite | `executor_id="local"` (or `DBOS__VMID`); `application_version` = md5 of workflow source → **a code change strands old PENDING work**; `max_recovery_attempts=100` then dead-letter. PROVEN |
| Commercial boundary | Conductor/Cloud gives multi-executor automatic recovery + UI (gating in code PROVEN; feature description DOCUMENTED_CLAIM). Client MIT. |
| Queues/retries | worker_concurrency, global_concurrency, rate limit, priority, dedup id, partitions, delay; step retries `max_attempts=3, interval=1.0, backoff=2.0, should_retry, timeout`; cancel/resume/fork/child workflows/send-recv/events. PROVEN |
| Dependency graph | code-level (child workflows, sequential steps). No declarative graph. |
| Tests | 54 files / ~1,222 test functions + 4-test chaos suite (5000-workflow load). Recovery tests read (`tests/test_dbos.py:342,394,471`) manipulate DB rows in-process rather than SIGKILL separate processes (INFERENCE; not fully audited). |
| PG 18.6 | all 36 migrations + all runs clean (psycopg 3.3.6, SQLAlchemy 2.1.1). Upstream CI matrix not checked (UNKNOWN). OBSERVED |
| Maintenance | 81 commits/90 d, 7 authors (one = 63). Company-backed, bus factor ≈1–2. 3 open issues (WebFetch), none on recovery; closed history UNKNOWN. Recovery fixes #786 #744 #717 #580. 3.0 removed APIs → churn (INFERENCE). |
| Setup | pip install 6.3 s; ~20 min to working experiment including 2 API fixes (`register_queue` must follow `launch()` in 3.x). OBSERVED |
| Fit (INFERENCE) | Simplest to *embed*; step replay works; survives PG blips. Failover is the gap: needs stable `DBOS__VMID` + pinned `application_version` + your own supervisor. TS/Go versions not inspected. |

## 3. Procrastinate — `procrastinate-org/procrastinate` (MIT)
**What:** Python library on Postgres only; 4 tables (`jobs`, `events`, `periodic_defers`, `workers`) + 18 plpgsql functions (`procrastinate/sql/schema.sql`); ~8.1k lines core. Deps: psycopg[pool] (v3), asgiref, attrs, croniter, dateutil, typing-extensions, packaging. PROVEN.

| Aspect | Finding |
|---|---|
| Claim | `FOR UPDATE OF jobs SKIP LOCKED`, `ORDER BY priority DESC, id`; `lock` string serialises jobs; `queueing_lock` dedups pending via unique index. PROVEN |
| Heartbeat/stalled | heartbeat 10 s, `stalled_worker_timeout` 30 s (worker.py:48-49). A worker prunes dead worker rows only **at its own startup** (worker.py:445), leaving the job in `doing` with `worker_id` NULL. `get_stalled_jobs()` (manager.py:223) only *lists*. **Nothing retries stalled jobs automatically**; docs (`retry_stalled_jobs.md`) say they stay "forever" unless you write a periodic task. Only builtin task is `remove_old_jobs`. PROVEN |
| Retry | `RetryStrategy(max_attempts, wait, linear_wait, exponential_wait, retry_exceptions)`, subclassable. NOTIFY only on insert and abort → retries wait for poll interval (default 5 s). PROVEN |
| Abort | async tasks cancelled; sync tasks poll `context.should_abort`. PROVEN |
| Dependency graph | **None.** `lock` ordering, `queueing_lock`, priority, `scheduled_at`, defer-from-task. A future-scheduled head job blocks its lock queue (locks.md; issue #1599). PROVEN/DOCUMENTED_CLAIM |
| Semantics | at-least-once. Chained `review` defer is not atomic with `work` completion → possible duplicate review (INFERENCE). Issue #1633: a presumed-stalled worker can still finish/retry after takeover (OBSERVED, WebFetch). |
| Tests | 644 test functions/36 files; stalled/heartbeat in `tests/integration/test_manager.py`, `tests/unit/test_worker.py`; no end-to-end SIGKILL/PG-crash test found (INFERENCE from grep). |
| PG 18.6 | CI matrix PG 14–18 (ci.yml:24-32); our runs on 18.6 worked. OBSERVED |
| Maintenance | 97 commits/90 d, 2 human authors (Jablon 55; 1,769 total) + bots; bus factor ≈1–2; 3,533 commits, tag 3.10.0 on PyPI. 12 open issues. OBSERVED |
| Setup | pip 9 s; `procrastinate schema --apply` one command; ≈10 min to write app + scripts. OBSERVED |
| Fit (INFERENCE) | Simplest ops of the five (PG + workers), SQL-queryable, solid retry. No checkpoints (a crashed job restarts from zero), no DAG, DIY stalled recovery, worker exits on any DB blip. Worker/reviewer loops and human waits would be hand-built on defer/`scheduled_at`. |

## 4. Restate — `restatedev/restate` (BSL 1.1; TS SDK MIT)
**What:** one 225 MB Rust binary running five roles (http-ingress, admin, worker, log-server, metadata-server); embedded Bifrost log + RocksDB; default 24 partitions, replication 1; invokes your **HTTP/2 service endpoint** and replays the journal. ~283k Rust LOC; Cargo.lock 984 packages. No Postgres/Kafka needed — and **Postgres cannot be the store** (metadata: raft/replicated/object-store/DynamoDB). PROVEN.

| Aspect | Finding |
|---|---|
| License | BSL 1.1 (LICENSE:1-66): Change License Apache-2.0, converts at earlier of 4 y after release / 4th anniversary of first public distribution *per version*. Additional Use Grant permits everything except a "Public Restate Platform Service" (managed offering where third parties register endpoints). Internal production use permitted; non-production always. PROVEN |
| Durability | log-server WAL + fsync by default (`crates/log-server/src/rocksdb_logstore/writer.rs:495-506`); disabling WAL flagged "[DANGEROUS]" (`types/src/config/log_server.rs:169-174`). PROVEN by reading; power-loss **not tested** (UNKNOWN). S3/GCS/Azure snapshots exist in code, off by default, untested (UNKNOWN). |
| Retry | default 500 ms initial ×2, max 1 m, 70 attempts then **PAUSE** (not fail); `on-max-attempts` pause/kill; per-step overrides via `ctx.run`. Idempotency keys 1 d. Inactivity timeout 1 m, abort timeout 10 m. PROVEN |
| Semantics | side effects at-least-once; recorded step results not replayed twice. |
| Dependency graph | none built-in; dependencies are code (sequential/parallel awaits) — INFERENCE. Service types Service/VirtualObject/Workflow registered (OBSERVED, not exercised); `sys_promise` table (durable promises) exists. |
| Observability | `restate` CLI (invocations, services, deployments, sql), SQL over DataFusion (18 tables: sys_invocation, sys_journal, sys_promise, sys_inbox…), UI at `/ui/` (200), Prometheus on by default. OBSERVED |
| Tests | ~1,206 test attributes/247 files; `cluster_chaos_test` (3 nodes, 60 s chaos), raft-metadata chaos, replicated-loglet tests; Jepsen nightly workflow (DOCUMENTED_CLAIM). **No in-repo single-node SIGKILL-with-SDK test found.** PROVEN by listing |
| Maintenance | 293 commits/90 d, 22 authors; top 6 = 86/73/56/22/13/12 → core team ≈3–4, company-backed. 91 tags. Open-issue count UNKNOWN. Recent recovery fixes: lost wakeup in vqueues (4b353e64b), stalled Lambda connections (310916ba3). OBSERVED |
| Footprint | 1 server + your endpoint + 1 registration `POST /deployments` (persisted). RSS ≈275 MB start, ≈307 MB after 60 invocations, 55–84 threads; data dir ≈220 MB on first start. npm install 11 s; ≈2 min to running server. Default bind `[::]` failed (RT0004, no IPv6) → needed `bind-ip=127.0.0.1`. OBSERVED |
| Fit (INFERENCE) | Least operator work in our runs; but it is a **second stateful authority** (RocksDB) beside PG, workers are push-style HTTP endpoints (no claim/lease/pull), 1 m/10 m default timeouts mean multi-minute agent steps should be durable promises completed externally, not one long `ctx.run`. |

## 5. Beads (`bd`) — `steveyegge/beads` (MIT)
**What:** a CLI task/dependency graph with claim/lease bookkeeping, meant as agent memory. **Not a worker runtime**: no dispatcher, supervisor, retry counter/backoff, worker registry, or reviewer role. PROVEN.

| Aspect | Finding |
|---|---|
| Storage | Dolt is the "default and only supported backend" (`init --help`); SQLite/JSONL legacy or export. Embedded mode default: Dolt inside `bd`, data in `.beads/embeddeddolt/`, file lock = one writer at a time; no daemon/port observed. Server mode needs a separate `dolt sql-server` pinned to Dolt 2.2.0 (DOCUMENTED_CLAIM; UNKNOWN here — no dolt CLI). `bd sql`/`bd doctor` unsupported in embedded mode → **no SQL view** in the default mode. **Not PostgreSQL.** OBSERVED |
| Claim | atomic compare-and-swap on a random `row_lock` cell (`issueops/claim.go`); re-claim by same actor = idempotent no-op. PROVEN |
| Lease | exists: `bd heartbeat`, `bd reclaim`; TTL hardcoded **5 min** (`issueops/lease.go:19-30`), settable only by Go context key (no CLI/config knob). **Nothing reclaims automatically**: only callers of `ReclaimExpiredLeases` are `bd reclaim` and its proxied variant; docs say run it from a supervisor timer. PROVEN by grep |
| Identity | unauthenticated `BEADS_ACTOR` string (INFERENCE on trust). Leases are node-local; multi-replica reclaim skips leases granted elsewhere unless `BEADS_NODE_ID`/`--any-replica`. |
| Dependencies | ~19 dep types (types.go:1277-1307); only `blocks`, `parent-child`, `conditional-blocks`, `waits-for` affect `ready` (types.go:1363). Gates (human/timer/gh:run/gh:pr/bead), molecules/formulas (TOML), wisps present, **not exercised**. "Evidence" = close reason, comments, metadata; **no structured evidence gate** (INFERENCE). |
| Tests | ~371k non-test Go LOC vs ~533k test LOC; 1,781 test files/9,874 Test funcs; lease/reclaim conformance (`backend/conformance/claim.go`), Dolt journal crash tests under `cmd/bd/doctor`. |
| Maintenance / stability | 10,959 commits; **1,558 in 90 d from 117 authors**; founder ≈6.7k commits; 131 tags (v1.3.0 2026-09-15; v1.3.1-rc.1). CHANGELOG has many "Breaking:" entries inside 1.x (lines 657, 1975, 2360, 3041, 3095, 3117). 26 commit subjects match "corruption", 26 match "lost/data loss"; 59 corruption/data-loss fixes in last 90 d (e.g. lost updates in server mode #6040, concurrent lost update #4732, claim/lease fix #4675, Dolt journal corruption #2934/#3457). **896 open issues** (WebFetch); #6929: server-mode migration swallows an error → "table not found: leases". PROVEN (commit subjects)/OBSERVED |
| Build/setup | default CGO build **failed** (ICU header `unicode/uregex.h` missing); `go build -tags gms_pure_go` worked, needs Go 1.26.7 toolchain; 3m40s first build incl. modules, 60 s rebuild; 214 MB binary; `bd init` 4.9 s, `bd create` ≈0.55 s each; init also installs git hooks + AGENTS.md unless `--skip-agents`. OBSERVED |
| Fit (INFERENCE) | Good *planning/memory layer* (graph, ready queue, fenced lease, cold-start state). Gaps: external timer for reclaim, fixed TTL, no retry policy, no reviewer semantics, no structured evidence, serialised ≈0.6 s writes, node-local leases, huge fast-moving codebase. |
